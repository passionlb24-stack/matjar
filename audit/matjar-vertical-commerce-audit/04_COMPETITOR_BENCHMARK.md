# 04 — مقارنة المنافسين عبر قطاعات مطجر (Competitor Benchmark)

مصفوفة أفضل الممارسات لكلّ قطاع مقابل السلوك الحالي لمطجر (المستند إلى أدلّة الـEvidence Brief فقط)، مع الفجوة والتكييف الموصى به وتعديل خاصّ بالسوق اللبناني. أنماط المنافسين مأخوذة من ممارسات منتجات معروفة على نطاق واسع؛ أيّ ادّعاء غير مؤكّد عن ميزة راهنة موسوم بـ **(للتحقّق)**. المحاور المقيَّمة لكلّ منافس: بنية البحث، صفحة القائمة/التفاصيل، الـCTA الرئيسي، الحقول المطلوبة، خطوات الحجز/الطلب، الإتاحة، عرض السعر، الثقة، الإلغاء، المراجعات، التأكيد، أدوات التاجر، الموبايل.

**ملاحظة عرضيّة عبر كل القطاعات:** مطجر بلا بوّابة دفع (COD / on-arrival) بحُكم السوق اللبناني، لذلك «الدفع» ليس فجوة بل خيار تصميم. الفجوات الحقيقيّة تتركّز في: بنية الـlisting/lead، الإتاحة بنطاق تواريخ (Model D)، الحقول المهيكلة، ونماذج التعامل E–L الغائبة. الجذر التقني المتكرّر: صفحة المتجر `store/[id]/page.tsx` تخلط `resolveStoreModules()` مع قوائم مكوّدة يدويًّا (`bookingCategories = {services, healthcare, realEstate}`)، فمحرّك الحجز الجيّد `place_booking` لا يظهر إلّا لثلاثة قطاعات.

|---|---|---|---|---|---|---|
| food | Uber Eats | بحث بالمطبخ/الصنف + تصفية بالوقت/التوصيل؛ صفحة صنف بـmodifier groups إلزاميّة (حجم، إضافات، درجة الطهي) | القائمة = products بـ`layout="menu"`؛ `product_options` مسطّحة (name+price) بلا group/required/min/max | لا مجموعات مُعدِّلات إلزاميّة → لا يمكن تمثيل «حجم/إضافات» بشكل صحيح | إضافة `modifier_groups` (required, min, max) على مستوى الصنف + عرضها كخطوة إلزاميّة قبل الإضافة للسلّة | دعم تسعير USD/LBP على كل مُعدِّل؛ ملاحظة صنف نصّيّة عربيّة |
| food | Deliveroo | ETA حيّ + رسوم توصيل حسب المنطقة + حدّ أدنى للطلب | `store_delivery_zones` (fee/min_order/free_over/eta) موجود ✅ عبر dropdown مناطق | تقدير ETA ثابت لا حيّ؛ لا مسافة/خريطة | إبقاء zones لكن إضافة ETA زمنيّ تقريبي حسب `prep_time`+المنطقة | المناطق اللبنانيّة (بيروت/جبل لبنان/شمال/جنوب/بقاع) كـzones جاهزة |

| food | Toast | إدارة مطبخ (KDS) + أوقات تحضير لكل صنف + إيقاف صنف نافد | وحدة `kitchen` (business tier) موجودة؛ `prep_time` نصّ حرّ على المتجر | prep_time غير مهيكل؛ لا إيقاف صنف على مستوى القائمة الحيّة | تحويل prep_time إلى رقم دقائق لكل صنف + toggle توفّر | يقلّل مكالمات wa.me «هل متوفّر؟» — قيمة كبيرة محليًّا |
| food | OpenTable | حجز طاولة منفصل عن الطلب (تاريخ/وقت/عدد أشخاص) | `ReservationForm` (date+time+party_size 1–50) يكتب `bookings` ✅ | جيّد؛ الفجوة أنّه غير مربوط بسياسة إلغاء/تذكير واضحة للمطاعم | ربط ReservationForm بـ`booking_cancel_hours` + تذكير | ثقافة الحجز الهاتفي سائدة؛ إبقاء wa.me كبديل |

## قائمة بنود تحتاج تحقّقًا خارجيًّا (Live Competitor Inspection)

يجب التحقّق ميدانيًّا (زيارة المنتج الحيّ) من الادّعاءات الموسومة **(للتحقّق)** قبل اعتمادها في التوصيات، أبرزها:

1. **Vezeeta / Practo (صحّة + صيدليّة + مختبر):** هل يدعمان فعلًا رفع الوصفة، حجز الفحوص المخبريّة بموعد، والاستشارة عن بُعد اليوم؟ (يؤثّر على قطاعَي pharmacy وhealthcare).
2. **Booking.com / Airbnb / Agoda / Vrbo / Expedia (فنادق/شاليهات):** التفاصيل الدقيقة لتسعير الموسم/العطلة، حدّ أدنى الليالي، ورسوم التنظيف — لتصميم Model D بدقّة.
3. **Zillow / Property Finder / Bayut / Rightmove (عقارات):** آليّة التقاط الـlead وطلب المعاينة وربط الوكيل الحاليّة — لتصميم Model H/I.
4. **AutoTrader / CarGurus / Turo / Rentalcars (سيّارات بيع/تأجير):** نمط الـlead مقابل الحجز، تقييم السعر، وحجز التأجير بنطاق — لإعادة تصنيف automotive.
5. **Fresha / Booksy / Treatwell / Mindbody / Glofox (تجميل + لياقة):** إدارة العضويّات/الباقات/قوائم الانتظار وسياسات الإلغاء الفعليّة — لتصميم Model L واستكمال Model C بعد فتح البوّابة.
6. **TaskRabbit / Thumbtack / Angi / Urban Company / Houzz (خدمات + مقاولات + مهنيّة):** بنية الـbrief، العروض المتعدّدة، وتتبّع المزوّد — لاستكمال Model F/G.
7. **Eventbrite / GetYourGuide / Viator (مناسبات + جولات):** بنية التذاكر (أنواع/كمّيّة/حاضر) وتأكيد QR — لبناء Model K.
8. **Toast / Uber Eats / Deliveroo / Talabat (مطاعم):** بنية modifier groups الإلزاميّة والطلب المجدول وتتبّع الحالة الحيّ — لاستكمال Model B.
9. **Instacart / Talabat Mart / Amazon Fresh (بقالة):** نوافذ التوصيل، البدائل عند النفاد، والتسعير بالوحدة.
10. **ClassPass / Glofox (لياقة):** حزم الحصص وسجلّ الحضور والتجديد.
