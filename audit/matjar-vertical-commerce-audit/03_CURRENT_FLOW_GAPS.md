# 03 — فجوات التدفّق الحالي (Current Flow Gaps)

> عرض مقطعي لأسوأ الفجوات عبر المنصّة، مرتّبة بالخطورة. التفصيل لكل قطاع في 06–15.

## أ. الفجوات الحرِجة (Critical) — تجعل التعامل مستحيلًا أو خاطئًا جوهريًّا

### C-1 · الإقامة تُحشَر في حجز موعد بالساعة (hospitality) 🔴
- **الخطأ:** الفندق/الشاليه يحصل على `TimeslotBooking` — حجز غرفة **بالساعة** ضمن يوم واحد. `bookings` لا يملك check-in/check-out كمدى، لا عدد ليالٍ، لا كبار/أطفال، لا عدد وحدات، لا سعر لليلة/موسمي.
- **من يتأثّر:** كل قطاع الفنادق والشاليهات (قطاع مُعلَن رقم 12) — لا يستطيع أي فندق تشغيل حقيقي.
- **الحلّ:** محرّك Model D (18_DATABASE_API_GAPS #1). **ممنوع** استخدام نموذج الحجز الحالي للإقامة.

### C-2 · السيّارة تُباع بـ«أضف إلى السلّة» + دفع عند التوصيل (automotive) 🔴
- **الخطأ:** automotive = `commerce` → سيّارة تُشترى بـstepper كميّة + منطقة توصيل + «فكة لـ100$». لا lead، لا «تواصل مع المعرض»، لا «اطلب تجربة قيادة». التأجير (`rentals`) علَم يتيم بلا محرّك.
- **من يتأثّر:** كل معارض/تجّار السيّارات والتأجير.
- **الحلّ:** Model J (إعلان) + H (lead) للبيع، Model D للتأجير. **ممنوع** checkout للسيّارات.

### C-3 · العقار على رزنامة موعد عيادة، بلا التقاط lead (realEstate) 🔴
- **الخطأ:** realEstate في `bookingCategories` → العقار يُعرَض عبر `BookingPanel` (موعد بفترة زمنيّة يشبه العيادة)، يظهر فقط إن ضبط التاجر allocationMode/مدّة/ساعات — وإلّا لا شيء. تفاصيل المنتج CTA = «زر المتجر». **لا جدول leads، لا «اطلب معاينة/تواصل مع الوكيل».**
- **الحلّ:** Model I (إعلان) + H (lead). الـCTA الأساسي «اطلب معاينة».

### C-4 · محرّك المواعيد لا يظهر لقطاعاته (drift الربط) 🔴
- **الخطأ:** المحرّك الجيّد (`BookingPanel`/`place_booking`) مربوط يدويًّا بـ`{services, healthcare, realEstate}` فقط. **beauty، petCare، professional، education** تُعلن `appointments` لكن تسقط لشبكة منتجات عاديّة. ونموذج الطلب `ServiceRequestForm` مربوط بـ`services`/`healthcare` فقط → **professional، contractors، realEstate، automotive** تُعلن `requests` بلا نموذج طلب.
- **من يتأثّر:** صالونات، بيطريّون، محامون/محاسبون، مدارس، مقاولون — يظهرون كمتاجر منتجات.
- **الحلّ:** إصلاح واجهة صرف (**صفر قاعدة بيانات**) — اشتقاق العرض من الوحدات المُفعَّلة. **أعلى نسبة أثر/جهد في التقرير كلّه.**

## ب. الفجوات العالية (High)

### H-1 · العضويّات والدورات لا تُسجَّل — WhatsApp فقط (fitness/education)
`store_membership_plans`/`store_courses` بطاقات سعر + `wa.me`. لا صفّ اشتراك/تسجيل، لا انتهاء/تجديد، لا مقاعد/شهادة. النادي/المدرسة بلا سجلّ أعمال حقيقي.

### H-2 · لا تذاكر للفعاليّات (events)
حجز بالساعة على مورد؛ لا نوع تذكرة/كميّة/سعة لكل فعاليّة/بيانات حاضر. قاعة المناسبات تحتاج أيضًا حجزًا بتاريخ/مدّة/ضيوف.

### H-3 · الطعام بلا modifiers إلزاميّة ولا طلب مجدوَل (food)
`product_options` مسطّح (اختياري فقط، بلا group/required/min/max). لا «اختر الحجم (إلزامي)»، لا «اختر صنفين»، لا ملاحظة على الصنف، لا `scheduled_for`. `min_order` client-side فقط، `prep_time` نصّ حرّ.

### H-4 · الصيدليّة والمختبر في قطاع واحد بتدفّق تجاري (pharmacy)
خلط بيع OTC (Model A) مع حجز فحص/عيّنة منزليّة (Model C). لا رفع وصفة، لا قيود منتجات، لا إخلاء مسؤوليّة قانوني، لا مواعيد/باقات/صيام للمختبر.

### H-5 · الخدمات المهنيّة بلا brief مشروع (professional/contractors)
`service_requests` عامّ (وصف+عنوان+هاتف). لا نطاق/ميزانيّة/مهلة/رفع ملفّات، لا صور موقع، لا نطاق جغرافي، لا إسناد/تتبّع تنفيذ.

## ج. الفجوات المتوسّطة (Medium)

| الفجوة | القطاع | الأثر |
|---|---|---|
| لا بيع بالوزن/وحدات، لا فترات تسليم | farm/grocery | لا يبيع خضار بالكغ |
| فلاتر exact فقط (لا مدى سعر/مساحة/سنة/كم) | realEstate، automotive، electronics | بحث غير عملي |
| retail بلا حقول خاصّة (electronics/furniture) | retail | لا مواصفات/أبعاد/ضمان منظّمة |
| لا دليل مقاسات/سياسة إرجاع منظّمة | retail(fashion) | ثقة أقلّ، إرجاعات |
| بيانات الحيوان مفقودة عند الحجز | petCare | كشف بيطري ناقص |
| موارد/حصص بلا لائحة انتظار/تأكيد حضور | sportsCourts، events، fitness | تجربة أقلّ من bookings |
| checkout المنتج المفرد يختلف عن السلّة | كل commerce | فقدان zone/coupon/loyalty/guest |
| لا اكتمال ملف/شروط نشر | كلّها | متاجر تُنشَر فارغة |

## د. الجذر المشترك لأغلب الفجوات
1. **تدفّقان فقط (order/appointment) لـ12 نموذجًا.** الناقص: stay، lead، ticket، membership، والنسخ الغنيّة من request/quote.
2. **نظاما تحكّم متعارضان** (سِجِلّ الوحدات مقابل قوائم مبرمَجة) → drift يجعل الوحدات المُعلَنة لا تعمل.
3. **Onboarding ضحل** (8 حقول عامّة) بلا حقول قطاع ولا مؤشّر اكتمال → متاجر ناقصة الإعداد.
4. **لوحة أدمن شكليّة** لا تضبط سلوك القطاع.

## هـ. الترتيب المقترح للمعالجة
**MVP:** C-4 (drift، صفر DB) → C-1 (الإقامة) → C-2/C-3 (leads) → H-3 (modifiers). 
**Phase 2:** H-1 (عضويّات/تسجيل) → H-2 (تذاكر) → H-4 (فصل مختبر/وصفة) → فلاتر المدى → onboarding/اكتمال. 
**Phase 3:** توحيد الموارد/الحصص مع المحرّك → عربون يدوي → توحيد نظامَي القوائم → قوالب حالة/SEO من الأدمن.
