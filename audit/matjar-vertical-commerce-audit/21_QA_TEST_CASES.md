# 21 — حالات اختبار QA خاصّة بكلّ قطاع (Category-Specific Test Cases)

كلّ سيناريو مُرقّم بصيغة: **المدخل → المتوقّع (السلوك الصحيح)** ثمّ **[الحالة اليوم]** من الأدلّة. ❌=يفشل اليوم، ⚠️=جزئي، ✅=يمرّ. الشدّة عند الفشل: C/H/M/L.

## 1. food — مطاعم
1.1 طلب صنف بإضافة مطلوبة (حجم/إضافات) → يجب منع الإضافة للسلّة قبل اختيار المجموعة المطلوبة. **[❌ H — لا modifier groups required؛ options مسطّحة]**
1.2 ملاحظة على بند («بدون بصل») → تُحفظ مع order_item. **[❌ M — لا per-line note]**
1.3 طلب مجدول (بعد ساعتين) → حقل scheduled_for يُحفظ ويظهر للمطبخ. **[❌ H — لا scheduled_for]**
1.4 طلب توصيل خارج مناطق المتجر → يُمنع أو يُحذّر برسوم. **[✅ zones 0172]**
1.5 فكّة (change_for) 50$ لطلب 32$ → تُحفظ وتظهر للسائق. **[✅ change_for]**
1.6 حجز طاولة (تاريخ/وقت/party_size=6) → يُنشئ صفّ bookings منفصلًا عن الطلب. **[✅ ReservationForm/E — لكن بلا لوحة عرض للتاجر ⚠️]**
1.7 حجز طاولة party_size=60 → يُرفض (الحدّ 1–50). **[✅ حدّ موجود]**

## 2. retail — تسوّق
2.1 منتج بلونين ومقاسين → اختيار لون ثمّ مقاس، السعر/المخزون لكلّ توليفة. **[✅ 0181]**
2.2 إضافة توليفة نافدة المخزون للسلّة → تُمنع. **[✅ variant stock]**
2.3 checkout كزائر بلا حساب → place_guest_order يعيد حساب الأسعار خادميًّا. **[✅ 0053]**
2.4 كوبون منتهٍ → يُرفض عند الدفع. **[✅ coupons]**
2.5 خصم flash خارج نافذة الوقت → لا يُطبّق. **[✅ flash_start/end]**

## 3. services — خدمات
3.1 خدمة (30د) → اختيار مزوّد → فتحات صالحة ضمن ساعاته فقط. **[✅ place_booking/provider hours]**
3.2 حجز فتحة محجوزة لنفس المزوّد → يُمنع (GiST exclusion). **[✅ 0174]**
3.3 إعادة جدولة موعد → تُحدّث الفتحة وتُحرّر القديمة. **[✅ 0175]**
3.4 إلغاء داخل نافذة booking_cancel_hours → مسموح؛ خارجها → يُمنع/يُحذّر. **[✅ 0189]**
3.5 تذكير قبل الموعد → reminded_at يُضبط. **[✅ 0177]**
3.6 طلب خدمة مفتوحة (F) بلا موعد → نموذج طلب متاح. **[⚠️ service_requests موجود لكن النموذج غير مُتاح لكلّ الخدمات H]**

## 4. healthcare — عيادات
4.1 اختصاص → طبيب → فتحات ضمن ساعات الطبيب فقط. **[✅ provider_exclusive]**
4.2 حجز نفس الفتحة لنفس الطبيب من مريضين → الثاني يُمنع. **[✅ GiST]**
4.3 حجز فتحة لطبيب آخر بنفس الوقت → مسموح (لا تعارض). **[✅ per-provider]**
4.4 إعادة جدولة/إلغاء ضمن السياسة → يعمل. **[✅ 0175/0189]**
4.5 no-show → تُوسَم attendance، لا تُحتسب مكتملة. **[✅ 0176]**
4.6 تذكير موعد → يُرسل. **[✅ 0177]**

## 5. realEstate — عقارات
5.1 بحث «شقة للإيجار، 3 غرف، بيروت» بنطاق سعر → نتائج مُفلترة. **[⚠️ فلاتر exact-match بلا نطاقات H]**
5.2 قائمة تعرض خريطة موقع → **[❌ H — لا خريطة، lat/lng غير مُستخدَم في العقار]**
5.3 «اطلب معاينة» (اسم/هاتف/وقت مفضّل) → يُنشئ **lead**. **[❌ C — لا جدول leads؛ يُعامَل كـBookingPanel فتحة واحدة]**
5.4 lead يظهر في صندوق leads للوكيل → **[❌ C — غائب]**
5.5 متابعة الوكيل: new→contacted→viewing_scheduled→closed. **[❌ C — لا مسار lead]**
5.6 CTA الأساسي = «اطلب معاينة» لا «زيارة المتجر». **[❌ H — الحالي «Visit store»/WhatsApp]**

## 6. automotive — سيارات
6.1 فلترة (brand+year+نطاق سعر) → نتائج. **[⚠️ فلاتر بلا نطاقات H]**
6.2 قائمة سيّارة → CTA «تواصل/احجز تجربة قيادة» يُنشئ **lead**. **[❌ C — الحالي add-to-cart COD «شراء بالدفع عند التسليم»]**
6.3 lead تجربة قيادة يظهر للمعرض. **[❌ C — لا leads]**
6.4 تأجير: اختيار مدى تواريخ → منع تداخل مع حجز قائم. **[❌ C — لا date-range؛ يُعامَل commerce]**
6.5 تأجير: سعر كلّي = أيّام × سعر/يوم. **[❌ C — غائب]**

## 7. beauty — تجميل
7.1 خدمة → أخصائيّة → تقويم فتحات يظهر علنًا. **[❌ H — appointments معلن لكن UI يسقط لشبكة منتجات خارج {services,healthcare,realEstate}]**
7.2 منع تعارض فتحة لنفس الأخصائيّة. **[⚠️ المحرّك جاهز لكن غير مُتاح للقطاع]**
7.3 تذكير/no-show. **[⚠️ جاهز عند تفعيل المحرّك]**
7.4 (بعد الإصلاح) توسيع البوّابة → تظهر BookingPanel. **[إصلاح منخفض الجهد]**

## 8. fitness — لياقة
8.1 شراء عضويّة (شهريّة) → **صفّ اشتراك** بتاريخ بدء/انتهاء. **[❌ H — بطاقة سعر+WhatsApp، لا صفّ]**
8.2 حجز حصّة بسعة 10 والمقعد 11 → يُدفع لقائمة انتظار. **[❌ H — الحجز بسعة غير مربوط UI؛ waitlist 0178 موجود لكن غير مُفعّل للحصص]**
8.3 حصّة ممتلئة → CTA يتحوّل «انضمّ لقائمة الانتظار». **[❌ H]**
8.4 تذكير تجديد قبل انتهاء العضويّة. **[❌ M — لا سجلّ انتهاء]**
8.5 عضويّة منتهية → تظهر expired في السجلّ. **[❌ H]**

## 9. sportsCourts — ملاعب
9.1 ملعب → تاريخ → فتحة ساعيّة متاحة. **[✅ resources 0128 + محرّك]**
9.2 حجز فتحتين متتاليتين → منع تعارض. **[✅ GiST]**
9.3 تسعير ذروة/عطلة نهاية أسبوع → سعر أعلى. **[❌ M — سعر ثابت]**
9.4 إلغاء ضمن السياسة. **[✅ 0189]**

## 10. education — تعليم
10.1 تسجيل بدورة → **صفّ enrollment** بتاريخ/سعة. **[❌ H — بطاقة+WhatsApp، لا تسجيل]**
10.2 دورة ممتلئة → قائمة انتظار. **[❌ H]**
10.3 قائمة المسجّلين تظهر للمدرّس. **[❌ H — غائب]**
10.4 حصّة أسبوعيّة بجدول → تظهر. **[⚠️ store_classes موجود]**

## 11. events — مناسبات
11.1 فعالية بنوعَي تذاكر (عادي/VIP) بسعرين → اختيار نوع+كميّة. **[❌ H — لا نظام تذاكر؛ TimeslotBooking ساعي]**
11.2 كميّة تتجاوز السعة المتبقّية → تُمنع. **[❌ H]**
11.3 حدّ لكلّ مشترٍ (4 تذاكر) → يُطبّق. **[❌ M]**
11.4 حجز قاعة منفصل عن التذاكر. **[⚠️ حجز عامّ فقط]**
11.5 رمز/تأكيد حضور بعد الشراء. **[❌ M]**

## 12. hospitality — فنادق وشاليهات (الأهمّ)
12.1 بحث بتواريخ check-in/check-out + عدد الضيوف → وحدات متاحة فقط. **[❌ C — لا date-range؛ TimeslotBooking ساعي]**
12.2 اختيار مدى تواريخ يتداخل مع حجز قائم → يُمنع. **[❌ C]**
12.3 أيّام محجوزة تظهر معطّلة في التقويم. **[❌ C — لا تقويم إتاحة]**
12.4 السعر الكلّي = Σ سعر كلّ ليلة (بسعر العطلة/الموسم أعلى). **[❌ C — لا تسعير موسمي/عطلة]**
12.5 رسوم تنظيف تُضاف مرّة واحدة للإجمالي. **[❌ H]**
12.6 حدّ أدنى للّيالي (min-stay=2): إقامة ليلة واحدة تُرفض. **[❌ H]**
12.7 عرض السعر النهائي قبل الطلب (ليالٍ×سعر + تنظيف). **[❌ C]**
12.8 إرسال طلب حجز → التاجر يؤكّد (لا تأكيد فوري). **[❌ C]**
12.9 إلغاء ضمن سياسة الإلغاء. **[⚠️ 0189 عامّ، بلا سياسة إقامة]**
12.10 التاجر يحظر تواريخ (صيانة) → تُمنع من الحجز. **[❌ C — لا حظر تواريخ]**
12.11 سعة الوحدة (بالغين/أطفال): تجاوز السعة يُمنع. **[❌ H — لا حقول سعة إقامة]**

## 13. pharmacy — صيدليات
13.1 شراء منتج + توصيل COD. **[✅ orders]**
13.2 رفع صورة وصفة → طلب مراجعة للصيدلي. **[❌ M — لا طلب وصفة]**
13.3 حجز موعد مختبر → فتحة. **[⚠️ يحتاج تفعيل المحرّك]**

## 14. petCare — عناية بالحيوانات
14.1 خدمة بيطريّة → مزوّد → تقويم فتحات علنًا. **[❌ H — appointments معلن، UI يسقط لشبكة منتجات]**
14.2 إيواء بمدى تواريخ → منع تداخل. **[❌ C — لا date-range]**
14.3 شراء منتج (A). **[✅]**
14.4 (بعد الإصلاح) توسيع البوّابة → BookingPanel. **[إصلاح منخفض الجهد]**

## 15. professional — خدمات مهنيّة
15.1 خدمة → «اطلب عرض سعر» بنموذج brief (نطاق/ميزانية/مهلة/ملفّات). **[❌ H — النموذج مقيّد services/healthcare؛ لا brief منظّم]**
15.2 التاجر يردّ بعرض سعر (quote_amount/note). **[⚠️ DB موجود، النموذج العامّ غير مُتاح]**
15.3 قبول العرض → in_progress → completed. **[✅ manage_service_request lifecycle]**
15.4 حجز استشارة (C). **[❌ يحتاج تفعيل المحرّك للقطاع]**

## 16. contractors — مقاولات
16.1 «اطلب زيارة موقع» بـbrief + صور المشكلة + إلحاح. **[❌ H — لا صور/إلحاح؛ النموذج غير مُتاح UI]**
16.2 عرض سعر بعد الزيارة → مسار quoted. **[⚠️ DB موجود، UI ناقص]**
16.3 قبول → تنفيذ → تسليم. **[✅ lifecycle]**

## 17. farm — مزارع
17.1 شراء منتج بالوحدة/الوزن + توصيل. **[✅ orders]**
17.2 حقل يوم توصيل/حصاد. **[❌ L — لا حقل يوم]**
17.3 اشتراك صندوق أسبوعي (L). **[❌ M — غائب]**

## سيناريوهات عابرة للمنصّة (Cross-Cutting)
X1 إنشاء متجر بـbusiness_type slug جديد غير مُعرّف بالكود → **يجب** ألّا تنهار صفحة المتجر. **[❌ C — تنهار (كلّ شيء مُفتاح بالـslug)]**
X2 تفعيل وحدة بلا بذور بيانات → يجب تغذية راجعة «أضِف أوّل عنصر»، لا فراغ صامت. **[❌ H — data-presence gating يُخفي دون رسالة]**
X3 قطاع يعلن feature (appointments/requests) → يجب أن تظهر الواجهة المقابلة. **[❌ H — drift سجلّ↔صفحة: beauty/petCare/professional/education/contractors]**
X4 تبديل اللغة يحافظ على الصفحة. **[✅ feedback batch]**
X5 مؤشّر اكتمال ملفّ + قائمة go-live عند الإنشاء. **[❌ H — onboarding شاشة واحدة بلا checklist]**
X6 حدّ منتجات حسب الخطّة (free 3) → يُمنع الرابع. **[✅ plan-tiers]**
X7 طلب ضيف بمعدّل مرتفع (rate-limit) → يُمنع/يُبطّأ. **[⚠️ للتحقّق — مذكور كفجوة في تدقيق سابق]**
