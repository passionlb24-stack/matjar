# 20 — تهيئة القطاعات من Super Admin

## أ. الوضع الحالي — CRUD تسمية فوق قطاعات مبرمَجة

**الصفحة:** `admin/business-types` → `BusinessTypeManager`. **الجدول:** `business_types` أعمدته: `id, slug, name_ar, name_en, icon, sort_order, is_active, created_at, updated_at` — **لا أعمدة تهيئة سلوكيّة**.

| الأدمن **يقدر** يضبط | الأدمن **لا يقدر** يضبط (مبرمَج على slug) |
|---|---|
| الاسم عربي/إنجليزي | نموذج التعامل (commerce/booking) → `modules.ts` |
| slug | حزمة الوحدات + وحدات لوحة التحكّم + الهويّة → `sectors.ts` |
| الأيقونة (نصّ) | الحقول المطلوبة/الخاصّة → `attributes.ts` |
| الترتيب (sort_order) | الـCTA + أيّ أقسام تظهر → شروط مبرمَجة في الصفحة |
| تفعيل/تعطيل، إنشاء/حذف | مسار الحالة، قواعد الحجز/الإلغاء، الوثائق، شروط النشر |

**خطر حاد موثّق:** كل السلوك مُفهرَس بالكود على `slug`. إنشاء نوع عمل بـslug جديد من اللوحة يجعل `sectorConfig[category]` يرمي استثناءً → **تنكسر صفحة المتجر ولوحة الوحدات** (fallback إلى `retail` يعمل فقط حين يكون slug فارغًا، لا مجهولًا). أي: اللوحة تُوهِم بإضافة قطاع، لكنها آمنة فعليًّا فقط لـ17 قطاعًا مكتوبًا بالكود.

**التوصية بالنشر:** أضِف تحذيرًا في اللوحة بأن إنشاء slug خارج الـ17 المعروفة غير مدعوم — أو عطّل الإنشاء الحرّ — حتى يُبنى `sector_definitions` (17_DYNAMIC_CATEGORY_ENGINE).

## ب. `store_modules` — تعمل، لكن config معطّل

- التاجر (owner) في `/merchant/[id]/modules` يشغّل/يطفئ **وحدات القطاع الافتراضيّة فقط** (كلّها ON افتراضيًّا)؛ وحدات Pro مقفلة على الخطّة المجانيّة.
- عمود `store_modules.config jsonb` **موجود وغير مستخدَم** — لا واجهة لضبط أي وحدة (لا ساعات، لا سياسات، لا حقول).

## ج. ماذا يجب أن يتحكّم به Super Admin (الهدف)

لكل قطاع، عبر `sector_definitions` (config مقيّد بـenums):
- الاسم + التسلسل الهرمي (مجموعة العميل).
- **بدائيّة التعامل** (order/appointment/timeslot/stay/lead/quote/ticket/membership).
- الوحدات المتاحة + الوحدات الإلزاميّة.
- **الـCTA الأساسي/الثانوي** (نصّ + فعل).
- **مسار الحالة** (اختيار قالب).
- نموذج التسعير (fixed/per_night/per_hour/per_period/quote).
- قواعد الحجز/الإلغاء (نوافذ افتراضيّة).
- **الحقول** (من `sector_field_defs`، أنواع معدودة).
- فلاتر البحث (أيّ حقول قابلة للفلترة + مدى/exact).
- **متطلّبات الثقة/الوثائق** ونوعها (مثلًا رخصة مهنيّة للأطبّاء/المحامين).
- **شروط النشر** ومؤشّر اكتمال الملف.
- قالب SEO.

## د. التوصية: **هجين (Hybrid) — لا كامل ولا صرف**

| النهج | الحكم | السبب |
|---|---|---|
| قابل للتهيئة بالكامل (no-code/EAV) | ❌ | تحقّق واستعلام هشّان؛ أخطاء صامتة؛ أداء رديء |
| مبرمَج بالكامل (الحالي) | ❌ | لا يتوسّع؛ drift؛ الأدمن عاجز؛ خطر الانكسار |
| **هجين** | ✅ | **النواة** (محرّكات التعامل، أنواع الحقول، قوالب الحالة) بالكود؛ **الربط** (قطاع↔بدائيّة، CTA، وحدات، حقول من أنواع معدودة، فلاتر، شروط نشر) من الأدمن ضمن قيم مسموحة |

**القاعدة الذهبيّة:** الأدمن **يركّب** من قطع مبنيّة بالكود؛ لا **يخترع** سلوكًا. هذا يمنع كسر الصفحات ويبقي التحقّق موثوقًا، ويجعل «إضافة قطاع» عمليّة إعداد آمنة بدل نشر كود.

## هـ. مراحل التمكين
- **MVP:** تحذير/قفل الإنشاء الحرّ للـslug؛ إصلاح drift الربط (الصفحة تُشتَقّ من الوحدات).
- **Phase 2:** `sector_definitions` + `sector_field_defs`؛ ربط لوحة الأدمن بها (enums)؛ تفعيل `store_modules.config` لضبط وحدة.
- **Phase 3:** قوالب مسار الحالة + شروط النشر + مؤشّر اكتمال + قوالب SEO من اللوحة.
